# OXAIT — народний бенчмарк

**Сайт:** [https://baraniukconnection.github.io/OXAIT/]

Турнір шести ШІ-моделей: три етапи, кваліфікаційні раунди й секції, таблиця лідерів зліва і живе прев'ю робіт справа — ігри можна запустити прямо на сторінці.

Статичний сайт без збірки: HTML + CSS + JS. Оформлення — неонова «геймерська» арена на базі розмірів Oxygen Theme (`assets/css/oxygen-tokens.css`): HUD-рамки, підсвітка, сітка-підлога, сканлайни.

## Структура

```
index.html                 вхід (вибір мови UA/EN) і арена
data.js                    ← усі дані турніру: учасники, етапи, бали, роботи
assets/css/app.css         стилі арени
assets/js/app.js           логіка й маршрутизація
assets/img/                постер, іконка
entries/                   роботи учасників (генерується tools/sync_entries.py)
tools/sync_entries.py      синхронізація робіт з HDD
entries/_template/         зразок роботи-гри
```

## Як додати роботи

Роботи зберігаються на HDD у `HDDWork/OXAIT/<раунд>/<учасник>/`:

```
OXAIT/
  Q1/
    Claude/   snake3D.html  tetris.html
    ChatGPT/  Snake3D.html  tetris.html
    ...
```

- раунд: `Q1`, `SEC1`, `Q2` (на сайті це sec-2), `Q3`, `SEC3`
- учасник: `Claude`, `ChatGPT`, `Gemini`, `Grok`, `GLM`, `QWEN`
- проєкт: `.html`-гра, папка з `index.html` (або `static/index.html` + `server.py`), зображення, відео, `.glb`/`.gltf`, `.md`/`.txt`
- зібраний фронтенд (Vite, React…): береться `dist/` (або `build/`, `out/`), шляхи `/assets/…` у копії стають відносними
- раунд може називатися й `sec-1`, учасник — `chat-GPT`: регістр і дефіси не важливі

Потім:

```bash
python3 tools/sync_entries.py
```

Скрипт копіює все в `entries/<етап>/<раунд>/<учасник>/` і складає `entries/manifest.js`. Назва проєкту береться з `<title>` гри (або з імені файлу). Якщо в учасника кілька проєктів, у прев'ю з'являється екран вибору «Варіант A / B / …».

### Проєкти з Python-сервером

GitHub Pages віддає лише файли й не виконує Python. Якщо в папці проєкту є `server.py` (або інший `.py`) з власним HTTP-обробником (`do_GET` / `do_POST`), а клієнт лежить у `index.html` чи `static/index.html`, скрипт синхронізації підключає до копії [`assets/js/pybridge.js`](assets/js/pybridge.js):

- оригінальний `server.py` запускається в браузері через [Pyodide](https://pyodide.org) (Python 3.13 у WebAssembly, разом із `sqlite3`);
- `fetch("/api/...")` клієнта йде в той самий обробник сервера, тільки без мережі;
- фонові потоки (ринок, тіки) виконуються по одній ітерації з тим інтервалом, який задає сам код;
- те, що сервер записує поруч із собою (збереження, SQLite), лежить в IndexedDB браузера відвідувача.

Код учасника не змінюється. У копії лише шляхи від кореня (`/js/app.js`) стають відносними, щоб працювати в підпапці. Перший запуск триває кілька секунд: браузер завантажує Python (~10 МБ, потім кешується). Сервер, який просто віддає статику (як `serve.py` для ES-модулів), не потрібен: такий проєкт працює як звичайний HTML.

## Як додати бали

`data.js` → `results`:

```js
"gamedev/q1": {
  order: ["claude", "chatgpt", "gemini", "grok", "glm", "qwen"],   // порядок при рівних балах
  entries: {
    claude: {
      pills: [[true, true, null], [true, true, true], [null, null, null]],   // 3 етапи × 3 таблетки
      // status: "out",                                                     // вибув — червоний рядок унизу
      note: { uk: "Коментар журі", en: "Jury note" }
    }
  }
}
```

Кількість груп по 3 таблетки задає поле `stages` раунду в `stages[...].rounds` (за замовчуванням 3; `stages: 0` — раунд без балів, лише перегляд робіт). Таблетка: `null` — порожня (ще не оцінено), `true` — заповнена (1 бал), `false` — оцінено на 0 (червона), число — заповнена з цифрою. Бали сумуються, таблиця сортується за ними (рівні бали ділять місце, наступне місце — без пропуску: 1, 1, 2), вибулі (`status: "out"`) — внизу червоним. Назви трьох груп таблеток — `groups` у `data.js` (можна перевизначити для окремого раунду). У групи раунду можна додати `match` — регулярний вираз по імені файлу чи назві проєкту; тоді проєкти розкладаються по етапах і йдуть у їхньому порядку (A — етап I, B — етап II…), а на картках видно етап. Група без `match` забирає все, що не підійшло до інших:

```js
groups: [
  { uk: "Етап I · Snake 3D", en: "Stage I · Snake 3D", match: "snake" },
  { uk: "Етап II · Тетріс",  en: "Stage II · Tetris",  match: "tetris" },
  { uk: "Етап III · Платформер", en: "Stage III · Platformer" }
]
```

Проєкт можна додати й вручну, без скрипта: `outputs: [{ type: "iframe", title: "...", src: "entries/..." }]` (типи: `iframe`, `image`, `video`, `model`, `text`).

### Вкладка-стаття (висновки)

Раунд з `type: "article"` показується як стаття замість таблиці: зображення `image` закріплене зліва, справа блоки тексту з `article`. Блок з `who: ["claude"]` оформлюється карткою учасника (колір, аватар і місце в кожному раунді з балами; `about: "<етап>"` обмежує плашки одним етапом); блок без `who` — вступ. Висновки живуть в окремій вкладці «Висновки» (етап `conclusions`), кожна стаття — її раунд.

Проєкт поза заліком можна сховати: `hide: ["<id проєкту>"]` у записі учасника.

```js
{ id: "summary", code: "★", title: { uk: "Висновки", en: "Conclusions" }, type: "article",
  image: "assets/img/results-gamedev.webp",
  article: [
    { text: { uk: ["Вступ…"], en: ["Intro…"] } },
    { who: ["qwen", "glm"], text: { uk: ["Абзац…"], en: ["Paragraph…"] } }
  ] }
```

## Посилання

Кожен стан має свою адресу: `#/uk/gamedev/q1/claude/tetris` — мова, етап, раунд, учасник, проєкт. Посилання з мовою пропускає екран вибору мови.

## Локальний запуск

```bash
python3 -m http.server 8765
```

і відкрий <http://localhost:8765>.

## Оновлення сайту

```bash
python3 tools/sync_entries.py   # якщо додались нові роботи
git add -A && git commit -m "..." && git push
```

GitHub Pages сам перезбирає сайт з гілки `main` за хвилину-дві.
